\section{Definición del Problema u Oportunidad}
\azul{Esta sección expone la brecha existente entre la situación actual de la organización y el estado tecnológico deseado. Para formular un problema en ingeniería, se requiere estructurar el diagnóstico en tres dimensiones: identificar los síntomas (deficiencias operativas observables), establecer las causas subyacentes (limitaciones arquitectónicas, algorítmicas o procedimentales) y proyectar las consecuencias si el escenario no se interviene. La redacción culmina con la formulación explícita de la necesidad que justifica el trabajo desarrollado.}

\moradoc{\begin{ejemplo}
		El departamento de finanzas presenta una latencia de 48 horas en la consolidación de reportes mensuales (síntoma). Esta demora se origina por la extracción manual de registros desde tres bases de datos relacionales aisladas, careciendo de un proceso ETL unificado (causa). De persistir esta fragmentación, la gerencia continuará operando con información desactualizada, ralentizando las decisiones estratégicas (consecuencia). Por consiguiente, se requiere diseñar un mecanismo automatizado de integración de datos que garantice la consistencia de la información.
\end{ejemplo}}

\section{Desglose de Actividades y Tareas}\label{s:actividades}
\azul{El desglose de actividades constituye la descomposición jerárquica del proyecto informático. Cada objetivo específico se divide en operaciones algorítmicas o administrativas atómicas, carentes de ambigüedad. Esta precisión representa el insumo directo para asignar recursos y estimar duraciones \cite[p. ~106]{pmi2021pmbok}, mitigando tempranamente los riesgos en la calendarización del software.}

\begin{ejemplo}
	\moradoc{	\textbf{Objetivo Específico 1 [Concebir]: Levantar los requerimientos funcionales y reglas de negocio operantes.}
		\begin{itemize}
			\item \textbf{Actividad 1.1: Diagnóstico de los flujos de información actuales.}
			\begin{itemize}
				\item \textit{Tarea 1.1.1:} Entrevistar a los analistas del área contable para identificar latencias en la emisión de reportes.
				\item \textit{Tarea 1.1.2:} Tabular los volúmenes transaccionales históricos desde el sistema legado.
			\end{itemize}
		\end{itemize}}
		
		\moradoc{\textbf{Objetivo Específico 2 [Diseñar]: Modelar la estructura de la base de datos relacional.}
		\begin{itemize}
			\item \textbf{Actividad 2.1: Diseño de la arquitectura de persistencia.}
			\begin{itemize}
				\item \textit{Tarea 2.1.1:} Elaborar el esquema entidad-relación en Tercera Forma Normal (3FN) para el almacenamiento de facturas.
				\item \textit{Tarea 2.1.2:} Diagramar la secuencia de comunicación asíncrona para la integración con la API del Servicio de Impuestos Internos.
			\end{itemize}
		\end{itemize}}
		
	\moradoc{\textbf{Objetivo Específico 3 [Implementar]: Construir los componentes de software del módulo.}
		\begin{itemize}
			\item \textbf{Actividad 3.1: Codificación e integración de servicios.}
			\begin{itemize}
				\item \textit{Tarea 3.1.1:} Programar los \textit{endpoints} RESTful para la recepción de cargas útiles en formato JSON.
				\item \textit{Tarea 3.1.2:} Configurar el contenedor Docker aislando el entorno de despliegue.
			\end{itemize}
		\end{itemize}}
		
		\moradoc{\textbf{Objetivo Específico 4 [Operar]: Desplegar la solución en un entorno de pruebas controlado.}
		\begin{itemize}
			\item \textbf{Actividad 4.1: Validación de consistencia transaccional.}
			\begin{itemize}
				\item \textit{Tarea 4.1.1:} Ejecutar pruebas de estrés inyectando concurrencia simulada en el servidor de pruebas.
				\item \textit{Tarea 4.1.2:} Consolidar las métricas de rendimiento y tiempos de respuesta en el repositorio documental corporativo.
			\end{itemize}
		\end{itemize}}
\end{ejemplo}
